# timetreeloc · 家庭日历屏

> 把一台闲置 iPad 变成挂在墙上的全家共享日历。**纯静态 HTML + IndexedDB，数据不出这台设备，不需要任何后端。**

A wall-mounted family calendar that runs entirely in one iPad's browser — no backend, no build step, no dependencies, no network calls at runtime.

## 它解决什么

家里每个人的日程散在三个地方：你的工作日历、她的手机备忘录、老人记在纸上。想共用一块屏，
现成方案要么把家庭数据放上别人的服务器，要么就得一直开着家里的机器。

这个项目选了第三条路：**屏幕本身就是数据中心**。iPad 常亮挂在墙上，路过的人抬手就能看一眼、记一条；
所有数据写进这台设备的浏览器数据库；断网、拔网线、飞行模式全都照常工作。

代价写在 [下面](#这个取向的三条代价)，是明说的，不是事后才发现的。

## 现在能做什么

- **壁挂四页轮播**：今天清单 / 周视图 / 月视图 / 待办。3 米外可读的字号下限（2.2vmin），
  顶栏是时钟 + 日期 + 存储健康状态点。
- **三类记录，永不互相污染**：日程（进日历、可重复、可提醒）、待办（永不进日历、永不过期、
  不打勾就一直显示）、倒数日（不进日历，在右栏倒计时，带"每年"的自动滚年）。
- **整屏管理页九个 tab**：日历（月/周/日三种视图 + 成员筛选）、待办、倒数日、成员、主题、提醒、
  壁挂、备份、关于。不是弹窗，是占满视口的页面——壁挂屏上弹窗挡住内容会没法取消。
- **重复日程**：工作日 / 每周 / 每月同日 / 每年，带结束日期与例外日；
  编辑或删除任一次会问"仅此事件 / 此事件及以后 / 整个系列"。
- **两种触摸手势**（只在管理页）：把日程拖到另一格 = 改到那天；待办行左滑露删除、右滑露完成。
  滑动本身不执行破坏性操作，改数据的手势一律可撤销。
- **前台提醒**：到点弹横幅 + WebAudio 合成提示音，幂等键做到重启/刷新不重发不漏发，
  超过 30 分钟的过期提醒只标灰不补响。
- **备份是一等公民**：导出/导入 JSON（带校验和，按更新时间合并，永不静默删除），
  超过 14 天没备份就提示，并请求持久存储、显示占用与配额。
- **四套主题**：暖木（默认）/ 墨蓝 / 夜灰 / 纸白。组件里不写死一个颜色，全部引用令牌。
- 界面全中文，零网络字体，无任何埋点。

## 30 秒跑起来

需要 Node（只为跑测试）和一个静态服务器；应用本身不需要构建、不需要 `npm install`（**零依赖**）。

```bash
git clone https://github.com/yt3000/timetreeloc.git
cd timetreeloc
python -m http.server 8080       # 或任意静态服务器
# 打开 http://localhost:8080/app/     ← localhost 允许装 PWA，http://192.168.x.x 不允许
```

跑五套无头测试（**398 项**，全部用 Node 标准库 + 自写的 DOM / IndexedDB 替身）：

```bash
node app/test/local.mjs      # 54   领域语义 · 仓储读写 · 拖动改日期 · 备份
node app/test/render.mjs     # 80   无头驱动 handler 跑完整流程 · 标签配对与产物脏值
node app/test/gesture.mjs    # 57   真的派发 pointer 事件，验证手势行为与边界
node app/test/static.mjs     # 52   结构约束：零依赖 / 样式令牌 / SW 清单 / iOS 安装能力
node prototype/smoke.js      # 155  界面原型的渲染与交互回归
```

装到 iPad 上：用 iPad 的 Safari 打开 `https://` 地址 → 分享 → **添加到主屏幕**。
全屏、无地址栏、可离线。**iOS 的"添加到主屏幕"不读 `manifest`**，只认页面里的 Apple 标签，
所以服务器把 `.webmanifest` 的内容类型配错也不影响安装（安卓与桌面 Chrome 才需要管，见
[`app/DEPLOY.md`](app/DEPLOY.md)）。

## 这个取向的三条代价

明说，免得用的人事后才发现。

1. **录入只剩"走到屏跟前"一条路。** 家人手机写不进来。缓解是把"记一件事"压到 3 步内
   （默认选中日、默认成员、大按钮），但替代不了沙发上顺手记一条。
   **判据**：上线两周后若日程全靠一个人录，说明这条路不成立，届时得回头谈同步——
   别靠劝家人改习惯来证明方案。
2. **"不共享"不等于"不需要服务器"。** iPad 装 PWA 必须从 `https://`（或 `localhost`）首次打开，
   `file://` 双击这条路在 iPad 上不存在。所以代码仍需一个 HTTPS 来源——**只放代码，不碰数据**。
   GitHub Pages / Cloudflare Pages 都行，家里 Docker 只发静态文件也行。
3. **唯一副本 = 丢一次就全清零。** iOS 不承诺网页数据永久保留。所以备份是界面上一等公民功能，
   并有超期提醒。天天在用的常亮屏属于较安全的情形，但不能不备。

## 已验证 / 未验证

浏览器里没有 Node，所以测试用 IndexedDB 与 DOM 替身跑**真实模块代码**——验证的是逻辑本身
（迁移、软删、合并、版本递增、三选一与拖动落库、提醒幂等、每段交互真的改变了界面与数据）。
**没有真机，就还不能声称下面这些是对的**：

- 添加到主屏后的真实全屏尺寸与安全区（现按 1180×820 逻辑分辨率推算）
- IndexedDB 在 iOS 上的真实持久性：重启、系统升级、存储紧张之后数据是否还在，
  `navigator.storage.persist()` 是否真被授予 ← **本机方案最大的未知项**
- 手势手感：`touch-action` 在 iOS Safari 的实际行为、抬手后 click 的到达时机、阈值与露出宽度
- 网页音频在侧边静音开关两种状态下的实际响度；连续 72 小时常亮的发热
- 浅色主题（纸白/暖木）在夜间盘下会不会过亮
- 引导式访问能否防住小孩误触

## 两条不接受就要重谈的边界

1. **提醒可靠 = 那块屏亮着且停在这个应用里。** iOS 不让网页弹系统通知、Web Push 需经 Apple 通道、
   后台定时器冻结、静音键掐音频。真需要全屋叫醒，正解是联动智能音箱，而不是跟系统死磕。
2. **数据只有这一份。** 不做备份就等于赌 iOS 不清你的存储。
