## 0. 本轮确认的决策

| 议题 | v0.1 | **v0.2（现在）** |
|---|---|---|
| 数据存放 | iPad 本地 IndexedDB | v0.2 家里服务器 SQLite → **v0.8 Cloudflare D1（仍是 SQLite）** |
| 访问终端 | 仅 iPad | **iPad 壁挂 + 家人安卓手机浏览器 + 任意电脑** |
| 服务器角色 | 只读静态托管，可停 | **必须常驻，承载数据与 API** |
| 界面入口 | 两个主屏图标（壁挂 / 管理） | **单一入口，壁挂态为宿主，管理为覆盖层** |
| 运行形态 | PWA | PWA（不变，但意义变了，见 §1.2） |
| 技术栈 | 原生 JS + IndexedDB | **原生 JS + 服务端 Node 内置 SQLite（两端都零依赖）** |
| MVP 功能 | 月/周/日 + 成员色 + Kiosk + 提醒 | 同，另加**多端实时同步、待办清单、倒数日、四套主题** |

### 0.2 v0.3 增补了什么

| 变更 | 影响的子系统 | 为什么不是"加个列表"那么小 |
|---|---|---|
| 记录分三型 `event / todo / countdown` | 数据模型、展开引擎、编辑抽屉、备份 | 展开引擎必须**硬跳过**非 event，否则一条未打勾的待办会在月视图里赖一整天；三类共用一张表是为了不让待办长成第二套系统（`02` §1-6） |
| 管理页弹窗 → 整屏 | 状态机、防误触、自动回落 | 挂墙场景下"浮层暗示可随时关掉"是误导；整屏才有足够高度放月视图 |
| 壁挂分栏 60/40 → 70/30 + 轮播页 今天/本周/本月/待办 | 视觉规格 | 周/月壁挂版需要宽度与更大字号；右栏只留倒数日；"生日与纪念日"页删除。v0.4 又把待办从右栏小盒升为整页——3 米外读不动的列表等于不存在 |
| 主题 4 套 | 颜色令牌层 | 唯一的硬约束是**组件不得写死颜色**，这条要在 M1 就做对，事后补等于重写样式 |

待办带来的新风险见 §10 末行；产品判断是：**待办的价值在"一直被看见"，它的失败模式是"变成没人再看的垃圾场"**，所以规范里用三条硬规矩压住（不自动过期、不变红催办、壁挂端最多 8 条）。

### 0.1 相对 v0.1 的实质变更

**被推翻的结论（3 条）**

1. v0.1 §1 推荐"服务器只做静态托管、装完可停"——不再成立。服务器现在是数据权威，**停机 = 全家只能看最后一次缓存快照，不能写入**。
2. v0.1 §6.5 把"导出 JSON 备份"定为一等公民、且必须在客户端做——降级为辅助手段。主备份变成**服务端数据库文件定时快照**（在 NAS 上几乎是免费的能力）。
3. v0.1 §9 的"将来可演进到多端同步"已成为现实路径，不再是预留。相应地，`version`/乐观并发从"零成本保险"升级为**必须正确实现的核心**。

**新增的风险（v0.1 不存在的）**

| 新增风险 | 说明 | 应对 |
|---|---|---|
| 服务器单点 | 断电、NAS 休眠、Docker 崩溃都会让写入失效 | 客户端只读降级（§6.6）+ 容器 `restart: unless-stopped` + NAS 关闭硬盘休眠 |
| 内网 HTTPS 证书 | 安卓/ iOS 浏览器要求可信证书，否则多人首次访问都要过信任警告 | 优先公网域名 + DNS-01（§8），次选自建 CA 装到各设备 |
| 并发编辑冲突 | 两人同时改同一条日程 | 版本号 + 409 冲突提示（§6.7），不做静默覆盖 |
| 提醒重复轰炸 | 4 台设备前台时同一条提醒各自弹一次 | 提醒归属可配置，默认只在壁挂端发声（§6.3） |
| 出门即失联 | 局域网外打不开 | 明确接受；真要外网访问另说（§8.3），第一期不做穿透 |

**没有变的东西（值得说明为什么不变）**

`docs/02` 的实体字段、重复展开引擎、成员固定 8 色、3 米可读字号体系、以及 iOS 那套平台限制（不能弹系统通知、Web Push 走不通、后台定时器冻结）——这些和"数据存哪里"无关，v0.1 的结论继续有效。**尤其提醒能力的边界一点没有改善**：换服务端不会让 iPad 锁屏后还能响，只是现在可以由服务器告诉"哪台在线的设备"该响。

## 1. 这次改动解决了什么、又改变了什么

### 1.1 解决的是产品层面最致命的那条

v0.1 的最大风险不是技术，而是"必须走到那块屏跟前才能记一件事"——家人在沙发上、在公司、在群里看到一条安排时不会为它起身走到墙边。共享数据 + 手机浏览器直接写入之后，录入路径和微信聊天一样近，这个需求才成立。

### 1.2 但 PWA 的定位从"离线容器"降级为"启动器"

v0.1 里 Service Worker 是功能必需（IndexedDB 是主存储，离线可写）。v0.2 里数据的权威在服务端，所以：

- SW 仍然要装（预缓存 HTML/JS/CSS，秒开、服务器重启瞬间不白屏、添加到主屏有图标）；
- 但**运行时数据走 fetch，不依赖 SW 缓存**；
- 服务端 API 响应**绝不进 SW 缓存**（否则会出现"手机上改了、壁挂屏看到的是旧的"这类极难排查的鬼故事）。这条是硬规则，写进实现约定。

一句话概括新架构：**服务端是唯一事实来源，客户端是带缓存的视图。**

## 2. 设计原则（v0.2 修订）

1. **单一权威，多端视图**：只有服务端 SQLite 可信；客户端内存 store 是视图，IndexedDB 是断网兜底快照。
2. **局域网即边界**：不做账号体系（家庭内网），但所有**写**操作要求 4 位家庭 PIN，防客人/小孩误改；读不需要。
3. **降级可用**：服务器不可达时，界面照常渲染最后快照并明确标注"离线只读 · 数据截至 12:03"，而不是白屏或报错弹窗。
4. **两端零依赖**：客户端无框架无构建；服务端 `node:http` + `node:sqlite` 单文件，Docker 镜像不需要 `npm install`。
5. **冲突显式化**：宁可让用户看到"这条刚被别人改过"，也不做静默覆盖。

### 3.1 服务端为什么选 Node 内置 SQLite（实测确认）

`node:sqlite` 的 `DatabaseSync` 在本机 Node v24.21.0 实测可用（建表 / 参数化写入 / 查询全通过），配合 `node:http` 即可覆盖全部需求：

```
FROM node:24-alpine
COPY public/ /srv/public/
COPY server.js /srv/server.js
CMD ["node","/srv/server.js"]
```

镜像内**没有任何 npm 依赖**，不需要 `package-lock.json`，不会因为依赖库停更而烂掉——这一点对一个打算跑十年的家庭服务比任何功能都重要。SQLite 单文件对家庭数据量（数千条日程、几 MB）是过剩的。

放弃：Go 单二进制（交叉编译对本人更麻烦，Docker 里跑也没省事）、nginx+PHP（引入不熟的技术栈）、Postgres/CouchDB（为一个家庭场景起数据库服务太重，且 CouchDB 的复制协议在本场景无用）。

## 4. 分层架构（客户端）

```
视图层 view/     kioskHost（壁挂态）· overlay/(detail, editor, monthGrid, settings)
状态层 state/    store.js —— 唯一可变状态；订阅式重渲染；pending 写队列
同步层 sync/     api.js（fetch 封装 + 超时/降级）· stream.js（SSE 订阅 + 断线重连）
                sync.js（拉取增量 / 推 pending / 版本冲突处理）
领域层 domain/   expand.js · bucket.js · remind.js · time.js   ← 与 v0.1 完全一致，纯函数可单测
存储层 local/    snapshot.js（IndexedDB 只读快照，断网兜底）
```

依赖方向自上而下；`domain/` 依旧不碰 DOM 与网络，所以 v0.1 定的那套展开单测（25+ 用例）原样有效。

**与 v0.1 的关键差异**：原来的 `data/repo.js`（IndexedDB 门面）被 `sync/` 取代。Repository 接口没有消失，只是背后从"本地库"换成了"服务端 + 队列"。

## 5. 核心数据流

### 5.1 首次加载（冷启动 < 400ms 目标）

```
SSE 未连 → GET /api/state → 服务端返回全量 members/events/settings + revision
        → 渲染（IndexedDB 快照仅用于「服务端不可达」时的兜底，二者不混用来源标记）
```

家庭数据量小，**第一期直接全量拉取**，不做增量分页。等日程条目过 5000 再考虑 `?since=` 增量（接口里已预留 `revision` 参数，届时不改契约）。

### 5.2 写入（含离线排队）

```
用户点保存 → 乐观更新本地 store（界面立刻变，不等网络）
          → sync.push(event)：PUT /api/events/:id  带 If-Match: <version>
          → 200 → 用服务端返回的 version 覆盖本地
          → 409 → 冲突：拉最新版本，弹"这条刚被 X 改过，你的修改要覆盖还是放弃"
          → 网络失败 → 进 pending 队列，界面标"待同步"，下次成功或重连时补发
```

乐观更新是这套体验的命门：局域网内 RTT 通常 < 20ms，但 NAS 休眠唤醒后首请求可能 2 秒——如果界面等网络，壁挂屏会被拖成"点了没反应"。

### 5.3 多端一致

服务端每次写自增全局 `revision`，然后通过 SSE 广播 `{type:'changed', ids:[...], revision}`；客户端收到后按需重拉该条（而不是推完整数据，保持 SSE 帧极小）。iPad 壁挂端收到变更 → 重渲染当前页，**如果用户正在编辑则不打断**，只在抽屉顶部标"这条被别处改过"。

SSE 断线（NAS 重启、Wi-Fi 切换）→ 指数退避重连（1s/2s/4s…上限 30s），重连成功后强制补一次 `GET /api/state`，防止漏事件。

## 6. 关键子系统

### 6.1 服务端最小接口集

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/state?since=<rev>` | 全量或增量拉取（含 `revision`） |
| PUT | `/api/events/:id` | upsert，带 `If-Match` 版本号 → 409 或 200 |
| DELETE | `/api/events/:id` | 软删除（写墓碑），支持 `scope=one|future|all` |
| PUT | `/api/members/:id` | 成员增改（删除=归档） |
| GET | `/api/stream` | SSE 变更广播 |
| POST | `/api/auth/pin` | 换取写令牌（局域网内 4 位 PIN，见 §6.8） |
| GET | `/api/export` | 全库 JSON（备份/迁移用，需 PIN） |
| POST | `/api/import` | 导入合并（需 PIN，永不隐式删除） |
| GET | `/healthz` | 容器健康检查 |

契约细节、SQL schema、错误码见 `02-数据模型与服务端契约.md`。

### 6.2 展开引擎 / 提醒 / 视觉规范

**与 v0.1 一致，不重复**：见 `02` §5（RRULE-lite 与 25 条边界用例）、`03` §4（字号与色板）。

### 6.3 提醒：谁响、怎么不重复响

服务端只负责存储与调度信息，**发声由设备自己完成**（iOS 限制不变）。为避免全家设备同时响：

- `settings.alarmHost`：指定"主提醒设备"（默认 iPad 壁挂端），只有它发声；其他设备只在自己前台时显示静默横幅。
- 判定"我是主机"的方式：客户端在 `navigator.standalone` + 用户在设置里点"设为壁挂主机"后，把设备指纹写进服务端，SSE 心跳时刷新 `lastSeen`。壁挂主机 90 秒无心跳，其他设备不接管（家庭场景宁可不响，也不要半夜三台设备轮流响）。
- iOS 侧的硬限制全部保留且**不因共享而改善**：不能弹系统通知、Web Push 内网不可用、后台定时器冻结、静音开关会掐网页音频。所以"提醒可靠 = 那块屏亮着且在前台"这条 v0.1 的判断继续成立。

### 6.4 融合界面（壁挂态为宿主 + 管理覆盖层）

这是本轮第二个变更。原来的两个入口合成一个 `index.html`，用模式状态机切换，**产物只有一个文件**。原型已照此收敛：`prototype/kiosk.html` 就是那个唯一入口（v0.1 的 `index.html` 管理原型已删除，其月/周/日视图与设置面板全部并进来）。

```
KIOSK  常态：轮播、大字、无控件干扰
  │  点任意日程卡 ────────────→ DETAIL   该条详情（就地可编辑/删除）
  │  点右下 + / 长按空白 ──────→ EDITOR   新建抽屉（预填默认值）
  │  点右上齿轮（12 秒无操作自动淡出）→ SHEET    管理面板：月/周/日网格 + 成员 + 备份 + 设置
  │  任意操作后静止 60 秒 ─────→ 自动回 KIOSK
  └  引导式访问锁死在本页面，退出只能由 iPad 侧连按三次 Home 完成
```

防误触策略（这是把管理塞进壁挂屏的最大代价）：

- 覆盖层出现时**暂停轮播**，回到 KIOSK 后恢复；
- KIOSK 态下卡片只有"点开详情"一个动作，不响应滑动/长按（滑动改日期、长按快捷删除这类手势在挂墙屏上必然误触发，全部不做）；
- 齿轮默认透明度 15%，只在触摸后 3 秒内全显，降低"墙上有个可点的东西"的诱导；
- 危险操作（清空、导入、删除成员）在覆盖层内再套一次 PIN 确认；
- 抽屉的键盘弹起会压缩视口，`visualViewport` 监听后整体上移，不用 `position:fixed` 硬扛（iOS 已知坑）。

### 6.5 备份（角色反转）

- **主**：服务端 `/data/timetree.db` 用 NAS 快照或 cron 里 `sqlite3 .backup`（用 `node:sqlite` 的 `backup()` 亦可，无外部二进制）每日一次，保留 14 份；容器卷必须映射到宿主机持久目录，**不能只写在容器层**。
- **辅**：设置页保留"导出 JSON / 导入"，用途从"防 iOS 清存储"变成"搬家/换设备/给异地亲人"。
- `/api/export` 直接产出 §7 的备份格式，客户端只是转发保存。

### 6.6 断网与降级

| 情况 | 表现 |
|---|---|
| 服务器停机/网络不通 | 用 IndexedDB 最后快照渲染，顶栏灰条"离线只读 · 数据截至 HH:MM"，写操作进 pending 不丢 |
| 单条写入 409 | 弹冲突对话（覆盖 / 放弃 / 看一眼对方的版本） |
| SSE 断开 | 静默重连（指数退避），恢复后全量补拉；顶栏黄点提示 |
| 数据损坏（版本不识别） | 拒绝启动并提示从 `/api/export` 备份恢复，不做"猜测式迁移" |

### 6.7 并发与版本

每条记录一个整数 `version`，写时 `If-Match`。服务端 `UPDATE ... WHERE id=? AND version=?`，影响行数 0 → 409 + 当前版本。删除用墓碑（`deletedAt`）而非物理删，避免"一端删了、另一端还在改"的幽灵。墓碑 30 天后由服务端后台任务清理。

### 6.8 安全边界（诚实说明）

服务只监听局域网，无账号；写操作需 4 位 PIN（换 12 小时有效的写令牌）。**这不防入侵，只防误操作**——真实威胁模型是"家里来客人拿到手机能乱改"和"小孩点来点去"。若将来要做公网访问，必须整体重做（反向代理 + 强认证 + 每设备令牌），不在第一期，也不要在第一期偷偷留口子。

## 7. 部署

### 7.1 有域名（推荐）

Caddy 或 nginx + Let's Encrypt **DNS-01** 签发（无需开放端口到公网），内网用 `hosts`/内网 DNS 指到服务器 IP。各设备零证书配置，家人首次访问无警告。**多终端方案下强烈建议走这条**——v0.1 只有一台 iPad 要受信任警告，现在是每台家人手机都要过一遍，成本不可接受。

### 7.2 无域名（次选）

容器内 `node:sqlite` + 自签 HTTPS，或 Caddy `tls internal` 生成自建 CA。需要**每台设备**安装并信任根证书（iOS：描述文件 → 设置里打开完全信任；安卓：安装 CA 证书到设备）。可行，但每来一台新设备就要重复一遍，家人不会配合。

### 7.3 组合骨架

```yaml
# deploy/docker-compose.yml
services:
  timetreeloc:
    build: .                      # node:24-alpine + server.js + public/
    restart: unless-stopped
    ports: ["8443:8443"]
    volumes:
      - ./data:/data              # ← SQLite 权威副本，务必在宿主机持久盘
      - ./certs:/certs:ro
    environment:
      TT_DATA_DIR: /data
      TT_PORT: "8443"
      TT_PIN_HASH: "..."          # PIN 的 scrypt 哈希，不存明文
    healthcheck:
      test: ["CMD","wget","-qO-","http://127.0.0.1:8443/healthz"]
      interval: 30s
      retries: 3
```

服务器需常亮：在 NAS 上关掉该卷的硬盘休眠策略，或给 Docker 容器配 `no-hibernate` 类守护；这是新增的单点风险里最容易解决的一个。

## 9A. （已归档）v0.8 部署修订：Workers + D1

### 9A.1 换掉了什么、换来了什么

| | v0.2（NAS + Docker） | **v0.8（Workers + D1）** |
|---|---|---|
| 数据在哪 | 家里 NAS 的一块 SSD | Cloudflare（引擎仍是 SQLite，schema 平移） |
| 出门能否写 | 不能（除非再做穿透） | 能，天然可用 |
| 运维 | 卷挂载、容器权限、硬盘休眠、内网证书、备份脚本 | 基本没有：平台管存储、副本与 TLS |
| 断网影响 | 断公网仍可局域网读写 | **断网即只剩只读快照**——IndexedDB 兜底从"可选"升级为"必需" |
| 成本 | 电费与硬件 | 免费额度内 0 元 |

代价是家庭日程出境到第三方，这条由你明确确认接受。

### 9A.2 配额会改写设计（官方数字，2026-09）

- D1 免费：**每日 500 万行读、10 万行写**；单库 500MB、每账户 5GB。超额**不是降级只读，而是查询直接报错**。
- Workers 免费：**每日 10 万次请求**，单次 10ms CPU。

由此两条硬约束：

1. **增量同步是第一天就要对的东西，不是优化项。** 4 台设备若每分钟全量拉 500 行 ≈ 288 万行/天，逼近上限。
   实现：每行带全局 `revision`，`GET /api/state?since=<rev>` 无变化时**只读 meta 一行**返回 `changed:false`。
   本地测试已验证：无变化时 events/members 的读取行数确实为 0。
2. **常亮屏靠 SSE 而不是轮询。** 一个长连接只算一次请求；轮询仅兜底且间隔 ≥60 秒。
   4 台设备 30 秒轮询 ≈ 1.15 万次/天（安全），5 秒轮询 ≈ 7 万次（加一台就爆）。

写入侧家庭场景远够用（每天几十次保存）。

### 9A.3 D1 与本地 SQLite 的差异，以及怎么躲

| 差异 | 影响 | 处理 |
|---|---|---|
| 不支持 `PRAGMA` | `journal_mode=WAL`、`busy_timeout` 无处安放 | 迁移 SQL 里**不写 PRAGMA**；只在本地适配器 `db.js` 里设，D1 由平台自管 |
| 无 `BEGIN/COMMIT` 语句 | 多行写需要原子性 | 用 `batch()`。官方文档称 "Batched statements are SQL transactions"、失败会 "aborts or rolls back the entire sequence" |
| 外键默认行为与 SQLite 不同 | 同一份 SQL 两边结果可能不一致 | **不依赖数据库外键**，两张表的关系在应用层保证，直接消掉差异源 |
| 迁移要分别 apply | 本地改了忘同步线上 | 脚本里 `migrate:local` 与 `migrate:remote` 并列，文档反复提醒 |
| 没有 `node:crypto` | PIN 哈希与令牌签名要换实现 | 全部改用 WebCrypto（PBKDF2 + HMAC），Node 24 与 Workers 都有 `globalThis.crypto`，同一份代码两边跑 |

**batch 的回滚语义目前只在本地事务下验证过**（测试里故意让第二条失败、断言第一条回滚）。
**D1 上必须再跑同一条断言才算数**——这是 S1 上线前的必做项，不能因为"文档这么说"就放过。

### 9A.4 访问控制现状（你选的：不可猜 URL + 读不鉴权）

按你的决定实现，但把风险说明白并留好退路：

- 读接口**当前不做任何鉴权**。拿到 URL 的人即可看到全家日程标题、成员名、出差区间——
  这等于对外公布"这家人 10/9–10/12 不在家"。
- 已做的两件零成本缓解：① 读权限单独收在 `auth.js` 的 `canRead()` 里，将来接 Cloudflare Access 只改这一个函数；
  ② 所有响应带 `X-Robots-Tag: noindex`，因为**被搜索引擎收录是"不可猜 URL"最主要的泄露路径**。
- 建议你这边做到：子域用随机串（别放家庭姓氏或孩子名字）、URL 不进群聊、不上截图、
  注意 iPad 浏览器历史会随 Apple 账号同步。
- 写操作仍需 4 位 PIN 换 12 小时令牌；PIN 只存 PBKDF2 派生值，不落明文。

哪天觉得不对劲，加 Access 是配置级改动而非重构——这是留这个接缝的唯一理由。

### 9A.5 本地开发顺序（含一个会让人误判的点）

```bash
cd server && npm install              # 只装 wrangler（开发工具），运行时零依赖
npm run migrate:local                 # 迁移应用到 .wrangler/state 下的 SQLite
npm run seed:local                    # 灌演示数据
node test/local.mjs                   # 30 项：schema / 并发 / 增量 / 原子写 / 鉴权 / 导出
npm run dev                           # http://localhost:8788
```

**localhost 是安全上下文，能装 PWA，但只有你这台机器能访问。
用 `--ip 0.0.0.0` 让 iPad 走 `http://内网IP:8788` 能看到界面，却装不了 PWA（非安全上下文，SW 不注册）。
真机壁挂体验要等 `wrangler deploy` 拿到 HTTPS 域名之后。**
顺序搞混会误以为"原型坏了"，所以写在这里。

上线还需要：`wrangler d1 create timetreeloc` → 把返回的 uuid 填进 `wrangler.toml` → `npm run migrate:remote`
→ 在 `.dev.vars`（本地）与 Cloudflare 环境变量（线上）分别设 `TT_PIN_HASH` 与 `TT_SECRET`。

### 9A.6 静态资源与 Service Worker 的分工变化

NAS 方案里 Docker 同时发静态文件和 API；现在静态文件交给 Workers Assets，API 留在 Worker。
SW 的职责也随之收窄：**只预缓存 HTML/JS/CSS**（秒开 + 服务器冷启动瞬间不白屏），
**API 响应一律 `no-store` 且绝不进 SW 缓存**——否则必然出现"手机上改了、壁挂屏还是旧的"这类难查问题。
API 响应头里已固定 `cache-control: no-store`。

## 9B. v0.9 最终取向：数据只存 iPad 本机

### 9B.1 决策与代价

| 项 | 决定 |
|---|---|
| 数据位置 | iPad 的 IndexedDB，**唯一副本** |
| 多设备共享 | **不做**。家人手机不能写入 |
| 后端 | **无**。`server/` 冻结归档 |
| 代码分发 | 仍需一个 HTTPS 来源（只放静态文件，不碰数据） |
| 备份 | **一等公民功能**，不是设置页里的隐藏按钮 |

三条必须认下来的代价：

1. **录入只剩"走到屏跟前"一条路。** 挂墙屏是全家视线交汇点，但不是全家随身携带的设备。
   缓解手段是把"记一件事"压到 3 步以内（默认选中日、默认成员、大按钮），但替代不了沙发上顺手记一条。
   **判据**：上线两周后若壁挂屏右栏待办常年为空、日程全靠你一个人录入，说明这条路走不通，
   届时再谈同步——不要靠劝家人改习惯来证明方案成立。
2. **唯一副本意味着丢一次就全丢。** iOS 不承诺网页数据永久保留：存储紧张、系统升级、
   长期不用（未装到主屏的网页 7 天规则）都可能被清理。**天天在用的常亮屏是较安全的情形**，
   但仍需把导出做硬：见 §9B.3。
3. **仍需要一个 HTTPS 来源才能安装。** 见 §9B.2。

### 9B.2 代码从哪来（三选一，都不涉及数据）

| 方式 | 说明 | 适合 |
|---|---|---|
| **Cloudflare Pages 只放静态文件**（推荐） | 免费、自带可信 HTTPS、无需在家跑任何服务；数据始终在 iPad | 不想维护机器 |
| 家里 Docker 只发静态文件 | 无 API 无数据库；但 iPad 首次安装与日后更新需家里机器开着 | 完全不想用外部服务 |
| 电脑临时起服务 | `python -m http.server` + 自签证书，装完即关 | 一次性，日后每次更新都要重连电脑，最折腾 |

三者的共同点：**服务器上不存任何家庭数据**，所以"不共享、不出门"这条守得住。
差别只在"代码怎么送达"。选前两种时，日后想升级到多端共享，加一层 API 即可，客户端不用重写
（`app/db.js` 的 Repository 接口就是为此留的缝）。

### 9B.3 备份：从"可选功能"变成"必做"

- **导出**：生成 `timetreeloc-backup-YYYYMMDD-HHmm.json`（含 schemaVersion、成员、设置、全部记录、校验和），
  经 `<a download>` 落到"文件"App，用户可自行挪到 iCloud Drive 或 NAS。
  iOS 上没有 File System Access API，这是唯一可行路径。
- **导入**：校验 → 预览差异（新增 X / 更新 Y / 跳过 Z）→ 二次确认 → 按 `updatedAt` 合并，**永不隐式删除**。
- **哨兵**：设置页常驻"上次备份：N 天前"，超 14 天则每次冷启动提示一次（壁挂端不打扰）。
- **启动自检**：`navigator.storage.persist()` 请求持久存储并显示结果；`navigator.storage.estimate()`
  读配额余量，接近上限时提前告警而不是写失败才知道。

### 9B.4 客户端结构（v0.9 实际形态）

```
app/
  index.html          单一入口（壁挂态为宿主 + 整屏管理，同 prototype/kiosk.html）
  manifest.webmanifest / sw.js      可装 PWA、离线可用
  css/                主题令牌（四套）
  src/
    domain.js         纯函数：展开、分桶、提醒时刻、比较器   ← 不碰 DOM 与存储，可单测
    db.js             IndexedDB Repository（唯一数据出入口）
    backup.js         导出 / 导入 / 备份哨兵 / 配额自检
    sync.js           （留空占位）将来做多端时在此实现远端 Adapter
    state.js view/    状态与渲染
```

`db.js` 对外只暴露异步方法，界面层不感知 IndexedDB。将来若要做共享，只需在 `sync.js` 里
实现同一组方法指向远端，`db.js` 降级为本地缓存——这是当初讨论 D1 时留下的缝，现在仍然有效。

## 9C. v0.10 运行时定稿：纯浏览器

### 9C.1 一句话架构

```
静态文件（HTML/CSS/ES Modules）  →  iPad Safari / 已装 PWA
        ↓ 只读代码，不存数据
IndexedDB（timetreeloc v1）      ←  全家日程的唯一副本，就在这台 iPad 里
```

没有的部分：Node 服务、Docker、API、数据库服务、账号、鉴权、同步。
**ES Modules 与 Service Worker 都要求 HTTP(S) 来源**，所以"纯浏览器"不等于"双击 index.html 就能跑"——
开发期用任意静态文件服务器（`python -m http.server` 之类，纯目录服务，不是应用运行时），
线上用静态托管。这一条区别很重要，别把"静态托管"又理解成"要跑个服务"。

### 9C.2 代码放哪（只放代码，数据永远在本机）

| 方式 | 首次安装 | 日后更新 | 家里要开着什么 |
|---|---|---|---|
| **静态托管（Pages / GitHub Pages 等）** | iPad Safari 打开 HTTPS 地址 → 添加到主屏 | 推新文件即可，SW 提示"有新版" | 什么都不用开 |
| 家里 NAS / 路由器的静态目录 | 同内网打开 `https://…`（需自签证书并在 iPad 信任） | 拷文件 | 那台机器要开着 |
| 本机临时起服务 | 同网段 http 打开，**能看界面但装不了 PWA**（非安全上下文） | 每次都要重连 | 电脑 |

推荐第一种：免费、自带可信 HTTPS、不需要家里常开机器，而且**服务器上没有任何家庭数据**。

### 9C.3 这个简化换来什么、失去什么

换来：零运维、零成本、数据不出门、没有并发与同步问题（单机不需要 `version`/`If-Match`/`revision` 那套，
字段先留着但不使用，见 `docs/02` §1-6 与 §2 附录说明）。

失去：家人手机不能写入（唯一可能让这件事失败的因素，判据见 §9B.1）、
换设备要手动导备份、iOS 清理存储的风险由备份策略承担。

### 9C.4 目录与运行

```
app/
  index.html              入口壳（架构验证用；完整界面在 M2 迁入）
  manifest.webmanifest    可安装 PWA
  sw.js                   预缓存代码；IndexedDB 永不进 SW
  styles.css              四套主题令牌
  src/domain.js           纯函数：展开、比较器、待办/倒数日、提醒时刻
  src/db.js               IndexedDB 仓储（唯一数据出入口）
  src/backup.js           导出 / 导入 / 校验和 / 备份哨兵
  test/local.mjs          Node 里跑真实模块（仅开发期工具，不参与运行时）
prototype/kiosk.html      完整界面原型（内存假数据，用于评审视觉与交互）
```

`node app/test/local.mjs` 只是**开发期的测试工具**——运行时零依赖、零构建，
交付物就是一堆静态文件。

## 10. 风险登记（v0.2）

| 风险 | 等级 | 缓解 |
